## Implementation sequence

1. Implement every delta-table row as a pure transformation of base/current evaluations and entity correspondence.
2. Apply each catalog rule's significant-worsening formula; distinguish new entity, introduced rule match and worsening of an existing match.
3. Preserve existing/resolved results for JSON; exclusions/off rules are not resolved problems. Removed entity resolution carries entity-removed reason.
4. Handle unavailable base/current explicitly, emitting comparison issues without inventing base zero.
5. Exact moves retain lifecycle; signature/FQCN changes produce removed+new. A newly extracted complex method must not escape new-entity checking.
