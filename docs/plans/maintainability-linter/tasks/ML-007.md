## Implementation sequence

1. Add a metadata registry classifying every metric used by a gate as syntax-local, symbol-context, or project-global. Unclassified codes are conservatively unavailable, not syntax-safe.
2. Audit each safe-set visitor named by the contract; select only needed metrics and their existing derived-input closure. Do not call every visitor in local mode.
3. Add gate --analysis-scope local|project and setting resolution. Local legacy requested unsupported metrics produce explicit pending evaluation issues (consumed in ML-008).
4. Prove syntax measurements ignore missing unrelated classpath symbols; use independent expected CC/nesting/count values.
5. Document any safe-set removal justified by the actual visitor and pin it in the registry test.
