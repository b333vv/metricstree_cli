## Implementation sequence

1. Extract reusable @TempDir Git fixture helpers from GateCommandTest without changing assertions.
2. Replace line-based path parsing with binary/NUL parsing for tree, index, untracked and name-status records. Add APIs resolveCommit, mergeBases, treeEntries, indexEntries, untrackedPaths, readBlob and pathChanges.
3. Resolve revisions to SHAs before tree/blob operations. Distinguish missing manifest entries from read failures; remove fileAt's catch-all empty-on-error behavior.
4. Use ProcessBuilder argument lists, concurrent stdout/stderr drainage and bounded timeout; preserve interrupts and a bounded error excerpt. Keep binary blob stdout as bytes.
5. Keep thin compatibility wrappers needed by the old gate until ML-006; do not switch behavior yet.

## Implementation notes

- Commit: `ML-003: NUL-safe read-only Git access layer`.
- Files changed: rewritten `GitOps.java`; new `GitTreeEntry.java`, `GitPathChange.java`; new tests
  `GitOpsTest.java`, `GitFixture.java`; `GateCommandTest.java` moved onto the shared fixture.
- Behaviour:
  - Every manifest is parsed NUL-delimited from raw bytes: `ls-tree -r -z --full-tree`,
    `ls-files -s -z`, `ls-files --others --exclude-standard -z`, `diff --name-status -z -M`. A path
    containing a space, tab, newline, Cyrillic character or leading dash is one record, unmodified.
    New APIs: `resolveCommit`, `mergeBases`, `treeEntries`, `indexEntries`, `untrackedPaths`,
    `readBlob`, `pathChanges`.
  - **Absence now comes from the manifest, never from a failed read.** The old `fileAt` returned
    empty on any nonzero exit, so a corrupt repository, a missing object, a broken git binary and a
    genuinely new file were indistinguishable — and the base pass treated all four as "the file did not
    exist at base", reporting a new violation for content it had never managed to read. `readBlob`
    returns bytes or throws; `fileAt` asks the tree whether the path is there and only then reads.
  - `ProcessBuilder` argument vectors throughout, no shell string anywhere, and
    `rev-parse --verify --end-of-options` so a ref like `--upload-pack=...` is a ref and not a flag.
  - stdout and stderr are drained concurrently on dedicated daemon threads. The old code read stdout to
    completion first, which deadlocks as soon as git fills the stderr pipe — a real risk for the large
    `ls-tree` output this layer now issues. There is a 60s bounded timeout that kills only the child
    via `destroyForcibly`, restores the interrupt flag rather than swallowing it, and bounds the error
    excerpt.
  - `GitTreeEntry` keeps the mode as its own field so a symlink, gitlink or subtree is a visible
    unsupported input rather than a read that fails later. `GitPathChange` carries **both** paths for a
    rename, which is a correctness requirement, not fidelity: a renamed class's base content lives under
    the old path, and a single-path record would read the new path at the base revision, find nothing,
    and judge the class as brand new — failing it for changes it had already made.
  - `indexEntries` throws on a stage-nonzero entry rather than picking one of the three conflicting
    versions.
  - Nothing mutates the user's repository: every command is a read, and blob content is written only
    into a directory the caller owns.
  - Per ML-003 step 5, **behaviour is not switched yet**: `changedFiles` and `fileAt` remain as thin
    compatibility wrappers for the existing gate, and ML-006 replaces them. `changedFiles` collapses a
    rename to its new path — that loss is exactly what `pathChanges` fixes, which is why it is a
    wrapper and not a general method.
- Tests: `GitOpsTest` (10 tests) — `roundTripsUnusualPaths` creates a repository containing all five
  awkward name shapes and asserts each survives create → commit → manifest → read byte for byte;
  `readsBlobBytesUnchanged`, `stageContentDiffersFromDisk`, `badRefAndUnreadableObjectAreErrors`,
  `renameRecordKeepsBothPaths`, `additionAndDeletionAreDistinguished`, `unmergedIndexIsReported`,
  `untrackedPathsExcludeIgnoredFiles`, `mergeBasesAreReportedExplicitly`,
  `treeEntriesCarryTheModeSoUnsupportedInputsAreVisible`. The unmerged-index test produces a **real**
  merge conflict rather than fabricating an index. `GitFixture` was extracted from `GateCommandTest`
  with **no assertion changed**. `./gradlew check` green.
  Verified against the installed distribution in a throwaway repository: five awkward names
  (space, tab, newline, Cyrillic, leading dash) all counted — `PASSED: 5 changed files`.
- Compatibility changes: none user-visible. The gate's verdict is unchanged, which is the point of
  keeping the wrappers. The improvement is that files which were previously dropped from the analysis
  are now included, so a run over a repository with such names can report **more** findings than
  before, because it is finally analysing the whole change.
- Remaining limitations: blob content is read whole into memory (correct for source files, unbounded in
  principle for a very large blob). The untracked/index/symlink APIs exist but are not yet consumed —
  ML-004 and ML-005 use them to build the staged/worktree snapshots. `MAX_ERROR_CHARS` documents the
  ceiling for error text; `firstLine` currently keeps only the first line, so the constant is a
  documented bound rather than active truncation.
