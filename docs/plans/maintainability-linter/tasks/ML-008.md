## Implementation sequence

1. Track selected-file outcomes, including unsupported declaration kinds, excluded/deleted files and parser errors. Use parser-derived declaration inventory, not a regex guessed from source text.
2. Expose syntax support inventory from the library through an additive report field/overload; preserve old constructors. Do not implement record/enum metrics in this task.
3. Build conservative file/metric completeness from inventory, diagnostics and nonfinite/missing values; never replace missing values by zero.
4. Implement exact verdict precedence and required-vs-optional rules in the comparison contract. Legacy unsupported checks are required; base parse failures cannot yield a clean pass.
5. Add additive analysis metadata to legacy gate adapters; preserve stable logical paths. An incomplete run writes a report before returning exit 2.

## Implementation notes (fill during execution)

- Commit: (recorded in docs/PROGRESS.md)
- Tests: new `GateCompletenessTest` (9 tests); `MetricReportJsonWriter`/`CliObjectMapperContractTest`
  and `JsonContractGoldenTest` green without regeneration.
- Compatibility changes, all deliberate: (1) a new `INCOMPLETE` status with **exit 2** when a required
  check could not be evaluated — this makes a default `gate -p standard` run exit 2, because
  `standard` configures three dozen thresholds and `local` cannot measure most of them;
  `GateCommandTest.failOnSubsetDowngradesUnselectedTypes` was moved to `--analysis-scope project` so it
  still tests what it is named for, and a new test pins the INCOMPLETE behaviour. (2) Gate reports gain an
  additive `analysis` object; `status` may now be `INCOMPLETE`. (3) `MetricReport` gained a
  `syntaxSupport` component with the old two-arg constructor preserved, and it is `@JsonIgnore`d so the
  `analyze` catalogue contract and its goldens are unchanged. (4) The gate now applies
  `--exclude-file`/config exclusions itself (deriving an FQCN from the repository-relative path);
  previously the analyzer compared patterns against a source-root-relative FQCN it could not derive from
  explicit source units, so exclusions silently matched nothing.
- Remaining limitations: (1) **any changed file containing an `enum`, `record` or annotation type is
  now reported `unsupported-declaration`, and in a default local run that is a required gap → exit 2.**
  This is contract-correct (those declarations are genuinely not measured) and it is the single largest
  behavioural consequence of this task; supporting them is out of scope here. (2) Non-finite detection is
  limited to metrics the run was asked to check. (3) Completeness is per-file; there is no package-level
  attribution yet.
