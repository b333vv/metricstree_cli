## Implementation sequence

1. Implement case/label formats with project-level tuning/holdout validation and source/license provenance.
2. Seed synthetic positive/negative cases and counterexamples; never label them maintainer feedback.
3. Run packaged MetricsTree and optional supplied pinned PMD executable/config in disposable repos, retaining raw output/version/exits.
4. Summarize labels, actionable/valid rates, uncertainty, duplicates, overlap, review effort and missed-issue sample coverage.
5. Add review forms for sampled unflagged diffs and agent-fix side effects; retain disagreements before adjudication.
6. Document reproducible dry run without claiming adoption or population recall. Add a dedicated CI job for the stdlib evaluation tests; Gradle check does not run Python tests. The job uses bundled cases only and never downloads a corpus or competitor binary.
